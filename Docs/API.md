## Assets/Assets.hpp

Loads textures, meshes, fonts and sounds from the Assets folder, and remembers them: asking for the same file twice gives back the same object, already loaded.

Everything is handed out as a std::shared_ptr. An asset stays alive for as long as something uses it (a material, a component, the cache here).

- `struct Font` — A font ready to draw with: the glyph table and the atlas texture.
- `class Assets`

### Assets

- `std::string path(const std::string& name) const;` — The full path of a file in the Assets folder. With a project open, the project's Assets folder is looked in first and the engine's own second, so a project can use the built-in font and textures and also replace them.
- `void setProjectDirectory(std::string directory);` — The Assets folder of the open project; empty for none. Forgets everything loaded from files, since the same name may now mean another file.
- `const std::string& engineDirectory() const;` — The engine's own Assets folder.
- `void reload(const std::string& name = {});` — Forgets one file (or, with an empty name, every file) so that the next request reads it from disk again: what an editor calls when a file changes.
- `size_t refreshInPlace(const std::string& name);` — The file `name` changed: read it again into the objects already handed out, so that what uses them (meshes on screen, materials, pictures of the interface) changes at once. Sounds are read again the next time they are asked for. Returns how many objects changed. The GPU must be idle (the editor waits for it).
- `void preload(const std::string& name, MeshData data);` — A model already read (on another thread, while a scene loads in the background): the next mesh(name) makes it from this instead of reading the file.
- `void preloadPicture(const std::string& name, std::vector<uint8_t> pixels, int width, int height);` — A picture already decoded, the same way: four bytes a pixel, rows from the top. The next texture(name) is made from these pixels instead of reading the file.
- `void forgetPreloaded();` — What was read ahead and not asked for after all is let go.
- `std::shared_ptr<Texture> texture(const std::string& name, TextureFormat format = TextureFormat::RGBA8_sRGB);` — An image. Use RGBA8_sRGB for colors (the default) and RGBA8 for data such as normal maps.
- `std::shared_ptr<Mesh> mesh(const std::string& name);` — A Wavefront OBJ model, or one of the built-in shapes: "cube", "sphere", "plane", "cylinder".
- `std::shared_ptr<Material> material(const std::string& name);` — A material that is a file of its own (a `.material`), shared by everything that names it: change it and every mesh that uses it changes. Null if there is no such file.
- `void adoptMaterial(const std::string& name, std::shared_ptr<Material> material);` — Makes `material` the asset `name` from now on (the editor, when a material is saved as a file for the first time).
- `std::shared_ptr<Font> font(const std::string& name);` — A font baked by Tools/bake_font.py: `name`.png and `name`.txt.
- `std::shared_ptr<AudioClip> sound(const std::string& name);` — A WAV, FLAC or MP3 file.
- `std::shared_ptr<Texture> makeTexture(const std::vector<uint8_t>& pixels, int width, int height, TextureFormat format = TextureFormat::RGBA8_sRGB);` — A texture from pixels computed by the program: four bytes each (red, green, blue, alpha), row by row from the top. For noise, gradients, anything drawn by code.
- `std::shared_ptr<Mesh> cube();` — Shared unit shapes: a cube with sides of 1, a sphere and a cylinder of diameter 1, a 1 x 1 plane facing up. Scale them with the entity's Transform.
- `std::vector<std::string> listFiles(const std::string& folder, const std::string& extension) const;` — The files in a folder of Assets whose names end with `extension`, sorted, as names that texture() and mesh() accept: listFiles("Textures", ".png").

## Assets/Font.hpp

A font as a game sees it: one texture with every glyph in it (an atlas) and a table that says where each glyph is and how to place it.

The atlas stores a signed distance field: each texel holds the distance to the glyph's outline instead of plain coverage. The fragment shader turns that back into a sharp edge at any size, so one small texture serves both tiny labels and huge titles. Tools/bake_font.py produces the atlas and the metrics file.

- `struct Glyph` — One glyph. All values are in atlas texels, at the size the font was baked at.
- `struct FontMetrics`
- `uint32_t decodeUTF8(std::string_view text, size_t& index);` — Reads one Unicode code point from UTF-8 text and advances `index` past it.

### Glyph

- `float x = 0, y = 0, width = 0, height = 0;` — rectangle in the atlas
- `float offsetX = 0, offsetY = 0;` — from the pen position (top of the line) to the rectangle's top left
- `float advance = 0;` — how far the pen moves after this glyph

### FontMetrics

- `float bakedSize = 48;` — the font size, in texels, the atlas was rendered at
- `float distanceRange = 8;` — how many texels the distance field extends around an outline
- `static std::optional<FontMetrics> parse(std::string_view text);` — Parses the text format written by Tools/bake_font.py.
- `const Glyph* glyph(uint32_t codepoint) const;` — The glyph for a Unicode code point, falling back to '?' and then to nothing.
- `Vec2 measure(std::string_view text, float size) const;` — Width and height of `text` when drawn at `size`. Handles newlines.

## Assets/MeshData.hpp

A mesh on the CPU: positions, normals, tangents, texture coordinates and triangle indices. It knows nothing about Metal, so it can be built, edited and tested anywhere. Rendering/Mesh uploads it to the GPU.

Triangles are counter-clockwise when seen from outside. Texture coordinates have their origin at the top left. A tangent points toward increasing u; its w is the sign that makes  cross(normal, tangent) * w  point toward the top of the texture.

- `struct MeshData`

### MeshData

- `static constexpr size_t kFloatsPerVertex = 12;` — Floats per vertex in interleaved(): position 3, normal 3, tangent 4, uv 2.
- `std::vector<float> interleaved() const;` — The vertex buffer contents, in the layout the mesh shaders expect.
- `void computeNormals();` — Smooth normals from the triangles, weighted by triangle area.
- `void computeTangents();` — Tangents from the texture coordinates. Needs normals.
- `static MeshData cube(Vec3 size = Vec3{1, 1, 1}, float uvPerUnit = 0.0f);` — A box. Normally every face shows the whole texture once. With `uvPerUnit` above zero the texture instead repeats that many times per world unit, so that boxes of different sizes can share one material without stretching it.
- `static MeshData plane(float width = 1, float depth = 1, int subdivisions = 1, float uvScale = 1);` — A flat grid in the XZ plane, facing +Y. `uvScale` repeats the texture that many times.
- `static MeshData cylinder(float radius = 0.5f, float height = 1, int segments = 32);` — A capped cylinder around the Y axis.
- `static MeshData cone(float radius = 0.5f, float height = 1, int segments = 32);` — A cone around the Y axis, point up, with a flat base.
- `static MeshData heightfield(float width, float depth, int columns, int rows, const std::function<float(float, float)>& height, float uvScale = 1);` — Terrain: a grid in the XZ plane whose height at (x, z) is given by a function. `uvScale` repeats the texture that many times across the whole grid.
- `static std::optional<MeshData> parseOBJ(std::string_view text);` — Parses Wavefront OBJ text: v, vt, vn and f records, polygons of any size, negative indices. Materials and groups are ignored. Returns nothing if the text contains no faces.

## Audio/Audio.hpp

Sound output: connects the Mixer to the computer's speakers, and decodes audio files.

The device work is done by miniaudio, a single-file library; on a Mac it talks to Core Audio. All this class does is open the default output and hand miniaudio a function that asks the mixer for the next block of samples.

- `class Audio`

### Audio

- `explicit Audio(bool openDevice = true);` — With `openDevice` false nothing is played: used when rendering without a window.
- `bool isAvailable() const;` — False if no output device could be opened. Playing sounds is then harmless and silent.
- `Mixer& mixer();` — Everything else: volume, pitch and pan of a playing sound, the master volume.
- `static std::shared_ptr<AudioClip> loadClip(const std::string& path);` — Decodes a WAV, FLAC or MP3 file into memory. Returns nullptr and logs if it cannot.

## Audio/AudioClip.hpp

Sound as numbers: a clip is an array of samples between -1 and 1. Clips can be decoded from files by the Audio class, or generated here from a few parameters, which is how the sample games get their sound effects without shipping a single audio file.

- `struct AudioClip`
- `enum Waveform { Sine, Square, Triangle, Sawtooth, Noise }`
- `struct SynthParams` — One synthesized note.
- `AudioClip synthesizeSequence(const std::vector<SynthParams>& notes, int sampleRate = 44100);` — Several notes played one after another, as one clip.

### AudioClip

- `std::vector<float> samples;` — interleaved if there is more than one channel

### SynthParams

- `float frequency = 440.0f;` — in hertz, at the start
- `float frequencyEnd = 0.0f;` — if above zero, the pitch slides to this value
- `float duration = 0.2f;` — seconds
- `float attack = 0.005f;` — seconds to fade in: avoids a click
- `float release = 0.1f;` — seconds to fade out at the end
- `uint64_t seed = 1;` — for Waveform::Noise

## Audio/Mixer.hpp

Turns "play this clip" into the stream of samples a sound card wants.

The operating system asks for audio in small blocks, a few hundred times per second, on a thread of its own. Each time, the mixer walks its list of playing sounds ("voices"), reads the next piece of each clip at the right speed, scales it by its volume and pan, and adds everything together. That is all a software mixer is.

Every sound plays in a group (Effects, Music, Voices, Interface, or one of the game's own), each with its volume, so that a settings menu can lower the music and keep the effects. A group can duck under another: the music goes down while someone speaks, and back up after.

Rooms: the sounds of the groups that send to it go through a reverb too, set by the room the listener is in (a cave, a hall, a bathroom), and a sound behind a wall can be muffled.

The mixer has no idea what a sound card is: Audio (in Audio.hpp) connects it to one. That keeps this file plain C++ that can be tested by calling render() directly.

- `struct PlayOptions`
- `using SoundHandle = uint32_t;` — Identifies one playing sound. 0 means "no sound".
- `class Mixer`
- `struct SpatialGain` — The volume and pan that make a sound seem to come from a place in the world.
- `inline SpatialGain spatialize(const Mat4& listenerWorld, Vec3 position, float fullVolumeDistance = 2.0f, float maxDistance = 40.0f);` — `listenerWorld` is the world matrix of whoever is listening, usually the camera. The sound plays at full volume within `fullVolumeDistance` and is silent at `maxDistance`.

### PlayOptions

- `float pitch = 1.0f;` — 2 is an octave higher and twice as fast, 0.5 an octave lower
- `float pan = 0.0f;` — -1 left, 0 center, 1 right
- `int group = 0;` — Mixer::group("Music"); 0 is Effects
- `float muffle = 0;` — 0 clear, 1 as from behind a thick wall

### Mixer

- `SoundHandle play(std::shared_ptr<const AudioClip> clip, const PlayOptions& options = {});` — Starts playing a clip. Returns 0 if the clip is empty or too many sounds are playing.
- `void stop(SoundHandle handle);` — Stops a sound with a very short fade, so that cutting it does not click.
- `int group(const std::string& name);` — The group of this name, made if there is none yet. Effects (0), Music, Voices and Interface are there from the start; Music ducks under Voices.
- `void duck(int group, int under, float to = 0.3f, float attack = 0.15f, float release = 0.8f);` — While anything plays in `under`, `group` goes down to `to` of its volume (0.3: a third), in `attack` seconds, and back up in `release` once it is quiet. A negative `under` stops it.
- `void setGroupReverb(int group, float send);` — How much of a group's sounds goes into the room's reverb: 0 none (music, interface), 1 all.
- `float groupDucking(int group);` — How far the group is ducked now: 1 not at all.
- `void setReverb(float size, float damping, float wet);` — `size` 0 a small room to 1 a cathedral; `damping` 0 bright (stone, tiles) to 1 dull (curtains, a forest); `wet` how much of it is heard, 0 none. Changes are eased in.
- `void render(float* output, int frameCount);` — Writes `frameCount` stereo frames to `output` (left, right, left, right, ...). This is what the audio thread calls.

## Core/Engine.hpp

The engine in one object: it owns the window, the renderer, the scene, the physics world, input, audio and assets, and it runs the loop that ties them together.

Every frame does the same things in the same order:

1. read input
2. zero or more fixed steps: Game::fixedUpdate, then physics
3. Game::update, then Behavior components
4. remove destroyed entities, compute world matrices, move particles
5. Game::draw fills the 2D canvas
6. the renderer draws the scene, then the canvas on top

- `struct EngineConfig`
- `class Engine`

### EngineConfig

- `int width = 1280;` — of the window, in points
- `bool developerKeys = true;` — F1 statistics, F2 collider outlines, F3 full screen, F4 saves a screenshot.
- `std::string capturePath;` — If set, there is no window and no sound: the game runs `captureFrames` frames at exactly 60 per second, the last one is saved to this PNG file, and run() returns. This is how the engine is tested on machines nobody is looking at.
- `int captureScale = 1;` — pixels per point of the captured image: 2 gives a "Retina" picture
- `std::string executablePath;` — The program's own path (argv[0]): lets a packaged game find the Shaders and Assets folders next to its executable.
- `std::vector<std::string> arguments;` — Whatever fromArguments() did not recognize: a game's own options.
- `static EngineConfig fromArguments(int argc, char** argv, EngineConfig defaults);` — Starts from `defaults` and applies --width N, --height N, --fullscreen, --capture FILE.png, --frames N and --scale N from the command line.

### Engine

- `int run(Game& game);` — Runs the game until the window closes or quit() is called. Returns the exit code for main().
- `void begin(Game& game);` — run() in three parts, for platforms where the system owns the loop and calls the program once per display refresh (iOS): begin() once, frame() each time until it returns false, end() once.
- `void frameWhileEventsAreHeld();` — A frame that does not look at the window's events: drawn while the system holds them (a menu of the menu bar is open, the window is being resized), so that nothing stops. Only while a frame waits in the window's events, and never inside another one.
- `void setDeveloperKeys(bool on);` — F1 statistics and the profiler, F2 colliders, F3 full screen, F4 a screenshot: on in a development build.
- `void loadQuality(const std::string& settingsDirectory);` — The project's quality: read from its Settings/Quality.settings (none: High). Used by the renderer as each view is drawn.
- `bool hasAudio() const;` — false where there is no sound device
- `bool writeImage(const std::string& path, const std::vector<uint8_t>& pixels, int width, int height);` — Writes pixels (four bytes each: red, green, blue, alpha; rows from the top) as a PNG file.
- `DebugDraw& debug();` — Lines in 3D for the next frame: engine.debug().line(a, b, color).
- `Window* window();` — nullptr when running without a window (EngineConfig::capturePath).
- `Vec2 screenSize() const;` — The drawable area in points: what canvas coordinates and the mouse position are measured in.
- `void setFont(std::shared_ptr<Font> font);` — The font Canvas::text draws with. Starts as the engine's own font.
- `Entity activeCamera();` — The entity of the camera the renderer is using, if the scene has one.
- `Ray screenRay(Vec2 screenPoint) override;` — The ray from the camera through a point of the screen: what the mouse is pointing at.
- `SoundHandle playSoundAt(const std::shared_ptr<const AudioClip>& clip, Vec3 position, float volume = 1.0f, float pitch = 1.0f);` — Plays a sound as if it came from a place in the world, as heard from the camera.
- `void saveScreenshot(const std::string& path);` — Saves the next frame to a PNG file.
- `bool showsStatistics = false;` — F1
- `bool showsColliders = false;` — F2

## Core/Game.hpp

What a game provides: a handful of functions the engine calls at the right moments. Override the ones you need.

```cpp
struct MyGame : molten::Game {
    void start(molten::Engine& engine) override { /* build the scene */ }
    void update(molten::Engine& engine, float dt) override { /* every frame */ }
};

int main(int argc, char** argv) {
    molten::Engine engine(molten::EngineConfig::fromArguments(argc, argv));
    MyGame game;
    return engine.run(game);
}
```

- `class Game`

### Game

- `virtual void start(Engine& engine);` — Once, when everything is ready: load assets and create entities here.
- `virtual void fixedUpdate(Engine& engine, float dt);` — At a fixed rate (60 times per second), just before each physics step. Apply forces and change velocities here. A frame may run this zero, one or several times, so do not look for key presses here: read input in update() and remember what you need.
- `virtual void update(Engine& engine, float dt);` — Once per frame, before drawing. `dt` is the duration of the frame in seconds.
- `virtual void draw(Engine& engine, Canvas& canvas);` — Once per frame, after update(): draw the interface, in points from the top left.
- `virtual void drawOver(Engine& engine, Canvas& canvas);` — The same, over everything else, the scene's interface included: a splash, a fade.
- `virtual void shutdown(Engine& engine);` — Once, when the game is closing.

## Game/Component.hpp

Components a game declares, in a form the rest of the engine can use without knowing their C++ type: the editor shows and edits their fields, scene files save them, and the engine runs their code while the game plays.

A component is a plain struct. Declaring it takes one line after it:

```cpp
struct Spinner {
    float turnsPerSecond = 0.5f;
    molten::Vec3 axis{0, 1, 0};

    // Any of these, if the component does something:
    void start(molten::Engine& engine, molten::Entity self);
    void update(molten::Engine& engine, molten::Entity self, float dt);
    void fixedUpdate(molten::Engine& engine, molten::Entity self, float dt);
    void onCollision(molten::Engine& engine, molten::Entity self, molten::Entity other);
    void onTriggerEnter(molten::Engine& engine, molten::Entity self, molten::Entity other);
    void draw(molten::Engine& engine, molten::Entity self, molten::Canvas& canvas);
};
MOLTEN_COMPONENT(Spinner, MOLTEN_FIELD(turnsPerSecond), MOLTEN_FIELD(axis))
```

Fields may be float, int, bool, Vec2, Vec3, Vec4 and std::string. A field that is not listed still exists; it is just not shown or saved (a timer, a cached pointer).

- `enum FieldType { Float, Int, Bool, Vec2, Vec3, Vec4, String }`
- `struct Field` — One field of a component: its name, its type, and how to reach it in an object.
- `MOLTEN_COMPONENT(Type, ...)` — Declares a component type and the fields the editor shows and scenes save. Put it after the struct, at file level, in a .cpp file.
- `MOLTEN_FIELD(member)` — One field of the component being declared. Follow it with .range(0, 10), .color() or .help("...") to say how the editor presents it.

### Field

- `std::string name;` — as in the code: "turnsPerSecond"
- `std::function<void*(void* component)> address;` — The address of this field inside a component of the type it belongs to.
- `float minimum = 0, maximum = 0;` — equal: no limits
- `bool isColor = false;` — Vec3 and Vec4 only: edited with a color picker
- `std::vector<std::string> options;` — see choices()
- `std::string pick;` — What a text field holds, so that the editor offers what it can be instead of a place to type it (one wrong letter and nothing works): "sound", "picture", "prefab", "scene", "font", "model", "controller", "clip", "timeline", "graph", "material", "folder"           a file of the project's Assets, of that kind "entity", "child", "entityOrTag", "tag" an entity of the scene (by name), one under this one, a tag "bone", "bones", "animation"            of the entity's model: a bone, several, an animation in it "value", "message"                      a shared value's name, a message's name (those in use, or a new one) "action", "axis"                        an input action of the project, a button or an axis "state", "parameter"                    of the entity's Animator Controller Empty: words typed freely, for what is read by people (a button's label, a text).
- `std::string pickBy;` — The pick decided by another field of the component: When / Then's target is a sound for "Play sound", a scene for "Load scene"...  (that field's value, the pick for it)
- `bool isHidden = false;` — Kept with the scene but not shown in the Inspector: data the editor manages (the file of a terrain's heights, of foliage's copies).
- `Field& choices(std::vector<std::string> words);` — For a text field that is one of a few words: the inspector shows a list to choose from. MOLTEN_FIELD(drive).choices({"front", "rear", "all"})
- `Field& picks(std::string kind);` — What it holds, for the editor to offer (see `pick`): MOLTEN_FIELD(clip).picks("sound").
- `Field& picksBy(std::string field, std::vector<std::pair<std::string, std::string>> kinds);` — Its pick follows another field: picksBy("action1", {{"Play sound", "sound"}, {"Load scene", "scene"}}).
- `std::string label() const;` — "turnsPerSecond" as a label: "Turns Per Second".
- `std::string valueText(void* component) const;` — The field's value in an object as text ("0.5", "0 1 0", a string as it is), and back. These are what scene files hold.

## Game/GameModule.hpp

A game's own code, built as a dynamic library and loaded while the program runs.

The library needs no entry point. Loading it runs its MOLTEN_COMPONENT lines, and each declares a component type; that is all the engine needs to show the game's components in the editor, read them from scenes and run them.

A module can be replaced by a newer build without restarting (the editor does this when the code is rebuilt). The old library is never unloaded: objects it made may still be alive somewhere, and their code must stay where it is. A few megabytes of address space per rebuild is the price.

- `class GameModule`

### GameModule

The links are bodies that swing, sag, wrap round what they meet and are pulled by what hangs from them; one mesh is drawn along them: a tube for a rope, rings for a chain.

- `struct Rope`
- `std::vector<Vec3> hangingPoints(Vec3 from, Vec3 to, float length, int count);` — Points from `from` to `to`, `count` apart along a curve `length` long: straight when it is no longer than the distance, sagging under gravity when longer.
- `MeshData ropeTube(const std::vector<Vec3>& points, float radius, int sides = 8);` — A tube through the points, `radius` thick, with `sides` sides.
- `MeshData chainRings(const std::vector<Vec3>& points, float thickness);` — A ring for each stretch between two points, each turned a quarter from the one before.

### Rope

- `std::string to;` — the entity its end is tied to; empty: it hangs free
- `float length = 0;` — meters; 0: as far as `to` is (or 3 hanging free)
- `int links = 16;` — more: smoother, heavier to work out
- `float thickness = 0.04f;` — meters across
- `bool isChain = false;` — drawn as rings, a little stiffer
- `float mass = 2;` — of the whole rope, kilograms
- `float bend = 0;` — degrees each link bends at most from the next; 0: as a rope does
- `Entity look;` — what is drawn
- `std::vector<Vec3> points(const World& world) const;` — Where the links are now: from the start to the end, one point at each joint.

## Kit/LightProbeVolume.hpp

A Light Probe Volume, as Unity's light probe groups and Adaptive Probe Volumes: a box of the scene where light is baked into probes (Rendering/LightProbes.hpp), so that inside it rooms are as dark as their windows make them and walls glow with the light bounced off the floor. Put one round a building, a cave, a street between tall houses; outside every volume everything is lit by the sky as before.

The box is centered on the entity, `size` meters along the world's axes (times the entity's scale; its rotation is not used). Lighting > Bake Light Probes bakes all of the scene's volumes into one `.lighting` file beside the scene, which the scene then names. What moves (bodies that are not static) and what is seen through is left out of the bake; what is drawn with it is lit by it, moving or not.

- `struct LightProbeVolume`
- `struct LightingBakeJob` — What baking a world's scene needs, read from it: its triangles, its lights, its volumes. Read on the main thread (it reads the scene and the models' files); baked on any.
- `LightingBakeJob prepareLightingBake(World& world, const struct RenderSettings& look, int raysPerProbe = 256);` — `look` is the scene's sky, for how much of its light falls on what the rays hit.
- `std::string lightingFileFor(const std::string& sceneName);` — Where a scene's baked light is kept: "Scenes/Main.scene" has "Scenes/Main.lighting".

### LightProbeVolume

- `float spacing = 2.0f;` — meters between probes: 1 for rooms, 4 or more for open ground
- `float bounce = 1.0f;` — how much light the walls throw back: 1 as their colors say
- `ProbeVolumeDesc desc(const Transform& transform) const;` — Where its probes go, in the world.

## Kit/Kit.hpp

Components that come with the engine, for the things nearly every game needs: a player that moves, a camera that follows, things to collect, things that shoot and things that break, a score on the screen, a way to win and a way to start over.

They are ordinary components declared with MOLTEN_COMPONENT, with nothing the game's own code could not do: when one does not fit, copy it from Kit.cpp into the project and change it. A game made only of these needs no code at all.

All of them take a World, so a game built from them can be played without a screen, which is how the project templates are tested.

- `struct PlayerMover` — Moves its entity with the keyboard: W A S D and the arrow keys, Space to jump. On a dynamic body it steers the body's velocity (or pushes it, with `rolls`, for a ball); on a kinematic body or none it moves the entity directly.
- `struct Follow` — Keeps its entity (a camera, usually) at a fixed offset from another, moving smoothly.
- `struct Spin` — Turns its entity at a steady rate.
- `struct Shuttle` — Takes its entity to and fro between where it was put and `offset` from there: a platform, a target on its rail, a gate that opens and shuts. What is under it goes with it.
- `struct Mover` — Moves its entity at a steady velocity, or toward another entity.
- `struct Lifetime` — Removes its entity after some seconds: bullets, effects, anything that should not pile up. One that came from a pool (World::take, a Spawner) goes back to it instead.
- `struct Collectible` — Something to pick up. Needs a trigger collider. When the collector touches it, a shared value goes up and the entity is gone.
- `struct Health` — How much damage its entity can take. At zero the entity is removed.
- `struct Damage` — Hurts what it touches, if that has Health. Works with a trigger or a solid collider.
- `struct Shooter` — Spawns a prefab in front of its entity while a key is held: a gun.
- `struct LoadingScreen` — What is under it in the Hierarchy (a picture, "{loading:percent}", a bar of "loading") is shown while a scene loads in the background, and hidden otherwise. Put it in the scene that starts the loading: the menu, the level being left.
- `struct Spawner` — Spawns a prefab again and again around its entity: enemies, pickups, rain. In waves, if `count` says how many a wave has; reusing what was put back (World::take, Lifetime) so that hundreds come and go without being made and destroyed each time.
- `struct HudText` — Text on the screen. {name} in the text is replaced with a shared value: "Coins: {score}". `text` may hold values of the game in braces: "{score}" its number, "{abs:off|on}" a word for it, "{lap:time}" seconds as a time (1:07.4).
- `inline Vec2 placeOnScreen(Vec2 screen, Vec2 anchor, Vec2 offset);` — Where a piece of interface is on a screen of a size: its middle.
- `struct UIPanel` — A rectangle of color: a background for other pieces, a frame, a divider.
- `struct UIImage` — A picture: an icon, a logo, a portrait. `picture` is a file of Assets.
- `struct UIButton` — A button to click or to tap. While a finger (or the mouse) is on it, it holds a button action, as a key would; let go on it, it can also add to a shared value and load a scene: "Play" loads the first level, "+" adds one to {count}.
- `struct UIGauge` — A dial that shows a shared value: a speedometer, a rev counter, a boost gauge. An arc that fills, marks with numbers along it, a needle, and the value in the middle.
- `struct UIArc` — An arc of a ring, filled as far as a shared value says (all of it with no value): a dial's track, a timer's ring, a cooldown. Thickness as large as the radius makes a disc.
- `struct UIMarks` — Marks along an arc, long and numbered at each `every`, short between: a dial's scale.
- `struct UINeedle` — A needle turned as far along an arc as a shared value says.
- `struct UIBar` — A bar that shows a shared value as a share of its most: health, fuel, progress.
- `struct TouchStick` — A stick for a thumb, drawn on the screen: for phones and tablets, where there are no keys. It pushes two axis actions ("moveX" and "moveZ" unless told otherwise), so a game written for a keyboard or a controller is played by touch without changing a line. With a mouse, press on it and drag: that is how it is tried on a Mac.
- `struct TouchButton` — A round button for a thumb, drawn on the screen: it holds a button action ("jump", "fire") while a finger, or the mouse, is on it.
- `struct Goal` — Watches a shared value. When it reaches the target the game is won: a message appears, the shared value "won" becomes 1, and after a moment the next scene loads.
- `struct RestartWhenBelow` — Starts the scene over when its entity falls below a height: the player fell off.
- `struct ConstantSpeed` — Keeps a body moving at one speed whatever it bounces off: the ball of a brick game.
- `struct Breakable` — Removed when something bumps into it: a brick, a crate, a target.
- `struct Explosion` — A blast: once, when it appears, it pushes the bodies around it away and hurts what has Health. Put it on an entity with a particle emitter (Burst at Start) and a Lifetime, and that entity is an explosion to spawn wherever one is needed.
- `struct Flicker` — Makes a light waver like a flame.
- `struct AudioSource` — Plays a sound from its entity: music, an ambience, an engine. Starts with the scene, or when something calls play().
- `struct Buoyancy` — Makes a body float: below `waterLevel` it is pushed up, the more the deeper it is, and slowed as water slows things. On an entity with a RigidBody.
- `struct Boat` — A boat: pushed ahead and turned by its rudder, only while it floats. With a Buoyancy and a RigidBody. Driven by the move actions (W/S and A/D, the left stick), or by `throttle` and `steer` from code with `usesInput` off. It makes its Buoyancy's lengthwise drag small, as a hull's is. Writes the values "speed" (km/h) and "knots".

## Kit/Vehicles.hpp

The parts machines are made of, each a component of its own: a body that moves and turns, wheels, suspensions, tires that flatten, an engine behind a gearbox, wings, hinges for the surfaces that move, a propeller. A car is a body with four wheels and a motor; an aeroplane is a body with wings, a tail, three wheels and a propeller; a trike, a hovercraft with fins, a glider or a truck with six wheels are other ways of putting the same parts together.

How they fit:

- `VehicleBody` goes on the root entity. It is the thing that has mass, and it runs
```cpp
the simulation of every part below it in the hierarchy.
```

- A part goes on a child entity. Where the child is, and how it is turned, is where
```cpp
the part is and how it is set: a wing tilted up two degrees has two degrees of
incidence; a wheel placed at a corner is that corner's wheel.
```

- Controls (`DriveControls`, `FlightControls`, or your own code) write what the driver
```cpp
wants into `VehicleBody::controls`; parts read it from there.
```

The engine's own physics has no rotating bodies yet, so a vehicle moves its own. The ground is found with rays against the scene's colliders: anything with a collider can be driven on, landed on, or hit.

Like the rest of the kit these take a World, and are driven in tests without a screen.

- `struct Body6` — A rigid body with rotation: where it is, how it moves, and what is pushing it this step.
- `struct Controls` — What whoever is at the controls wants, for the parts to read.
- `struct VehicleBody` — The thing that has mass. Everything below it in the hierarchy that is a part (Wheel, Wing, Motor, Propeller, Bumper...) pushes on it.
- `struct Bumper` — A point of a vehicle that must not go through things: a nose, a wingtip, a roll bar. On a child entity of a VehicleBody.
- `struct WheelState` — One wheel as the simulation sees it. Read it for sounds, skid marks, dials.
- `struct Wheel` — A wheel. Put it on a child of a VehicleBody, where the wheel is when the vehicle stands. The entity is moved with the suspension and steered; a child called "Spin" is turned as the wheel turns: put the wheel's model there, with its axle along x. Alone it is a rigid wheel on a rigid leg; add Suspension and DeformableTire to it.
- `struct Suspension` — A spring and a damper between a Wheel and the body. On the same entity as the Wheel.
- `struct DeformableTire` — Air in the tire of a Wheel: it flattens under load, more when soft; a soft tire grips a little more and rolls harder. On the same entity as the Wheel.
- `struct Motor` — An engine behind an automatic gearbox, turning every driven Wheel of the vehicle. On the VehicleBody's entity or any child.
- `struct Wing` — A flat piece that makes lift and drag from the air meeting it: a wing, a tailplane, a fin, a spoiler on a car. On a child of a VehicleBody, placed where its lift acts. Its upper side is the entity's +y and its leading edge is toward -z: tilt the entity to set it at an angle, stand it on its side (turn it about z) to make a fin. Children with a Hinge are its moving parts.
- `struct Hinge` — A part that turns about an axis by what a control asks for: an aileron, an elevator, a rudder, a flap, a steering wheel. The entity is turned. Under a Wing it also changes what the wing does.
- `struct Propeller` — An engine with a propeller: pulls the vehicle along the entity's -z. A child called "Blades" (or the entity itself if there is none) is spun.
- `struct DriveControls` — A driver for a vehicle with wheels, reading the player's keys: W and S (the action moveZ) accelerate and brake, and reverse from a standstill; A and D steer; Space is the handbrake; 1 to 4 change the engine. On the VehicleBody's entity. Writes the values "speed" (km/h), "rpm" and "gear".
- `struct FlightControls` — A pilot's hands and feet, reading the player's keys: S and W (moveZ) pull and push the stick, A and D roll, Q and E are the rudder, Shift and Control the throttle, F the flaps, B the brakes. On the VehicleBody's entity. Writes the values "airspeed" (km/h), "altitude", "climb", "throttle", "flaps", "stall".
- `float engineTorque(const std::string& engine, float rpm);` — The torque an engine of a kind gives at a speed, with the pedal down. For dials and tests.
- `Entity vehicleOf(const Scene& scene, Entity part);` — The VehicleBody an entity is part of: its own, or the nearest above it.
- `Entity makeCar(World& world, Vec3 position, const std::string& engine = "i4", const std::string& drive = "rear");` — Builds a car out of parts, without models: a body with a Motor and DriveControls, and four wheels called "Wheel FL", "Wheel FR", "Wheel RL", "Wheel RR", each with a Suspension and a DeformableTire. `drive` is "front", "rear" or "all".
- `Entity makeAirplane(World& world, Vec3 position);` — Builds a light aeroplane out of parts, without models: wings with ailerons and flaps, a tailplane with an elevator, a fin with a rudder, three wheels, a propeller, bumpers.

## Core/Time.hpp

Frame timing and the fixed-step clock.

Rendering runs as fast as the display allows, with a different duration every frame. Physics is only stable and repeatable with a constant step. The classic answer is an accumulator: real time is poured in each frame and consumed in fixed-size steps. Whatever is left over, as a fraction of a step, is `alpha`: how far the renderer should blend from the previous physics state to the current one.

- `struct Time`

### Time

- `double elapsed = 0;` — seconds of game time since the start
- `float delta = 0;` — duration of this frame, scaled by timeScale
- `float fixedDelta = 1.0f / 60.0f;` — duration of one physics step
- `float alpha = 0;` — 0..1: position of this frame between two physics steps
- `float timeScale = 1.0f;` — 0 pauses, 0.5 is slow motion
- `float framesPerSecond = 0;` — smoothed
- `int maxStepsPerFrame = 5;` — after a long hitch, drop time instead of spiralling
- `int beginFrame(double realDelta);` — Starts a frame that lasted `realDelta` seconds. Returns how many fixed steps to run now.

## Physics/Physics.hpp

Arcade rigid-body physics: the kind most games want.

What it does: spheres, oriented boxes and capsules; gravity, bouncing and friction; static, kinematic (moved by the game) and dynamic (moved by forces) bodies; triggers, collision layers, raycasts and overlap queries; a fixed time step with interpolation.

What it leaves out, on purpose: bodies do not spin from impacts (rotation stays under the game's control), there are no joints, and fast objects can pass through thin ones. Those are the hard parts of a physics engine; when a game needs them, a dedicated library is the right tool.

Entities that take part in physics must not have a parent: their Transform is read and written as a world-space position.

- `enum BodyType { Static, is not pushed by anything: platforms, doors Dynamic }`
- `struct RigidBody`
- `struct Joint` — Ties a body to another, or to the world: a door on its hinges, a lamp on its chain, a trailer on its hook, the links of a rope. On an entity with a RigidBody.
- `struct Collider` — A shape for collision detection. Without a RigidBody on the same entity it is a static obstacle. Sizes are in world units and ignore Transform::scale.
- `struct Contact`
- `struct RaycastHit`
- `void worldPlace(const Transform& transform, Vec3& position, Quat& rotation);` — Where a collider without a body of its own stands in the world (under whatever it is under): its place and its turn, without the scale. For code that tests against colliders itself.
- `class Physics`

## Rendering/Canvas.hpp

Immediate-mode 2D drawing for HUDs, menus and 2D games.

"Immediate mode" means there are no 2D objects to keep around: every frame the game says what to draw, in order, and the canvas turns the calls into triangles. The renderer draws them in as few draw calls as possible (one per change of texture).

Coordinates are in points with the origin at the top left, like the window system's. Colors are sRGB with straight alpha, the values a color picker shows.

Edges are smoothed without multisampling: every shape that is not an upright rectangle gets a border one pixel wide that fades from its color to transparent. The same triangles and the same shader do everything; only the vertices know about it.

- `enum TextAlign { Left, Center, Right }`
- `inline Vec4 rgb(uint32_t hex, float alpha = 1.0f);` — A color from the usual hexadecimal notation: rgb(0xfe8b3c) is an orange.

## Rendering/Material.hpp

How a surface looks: the inputs of the physically based shader. The layout follows glTF's "metallic-roughness" model, the one most tools export.

- `enum AlphaMode { Opaque, sorted back to front, blended }`
- `struct Material` — Each factor multiplies the matching texture. A missing texture counts as white (or as a flat surface, for the normal map), so factors alone describe a plain material.
- `struct MeshRenderer` — Component: draws a mesh with a material at the entity's Transform.
- `struct Decal` — Many copies of an entity's mesh, drawn together in few draw calls: grass, trees, rocks, fence posts. Beside a MeshRenderer: its mesh and material are drawn at each of `places` (in the entity's space) instead of once at the entity. Copies farther than `drawDistance` meters from the camera are not drawn (0: all of them, however far). A decal: a picture projected down onto whatever is under it, inside the entity's box (its scale is its size: x by z across, y how deep it reaches). Dirt, cracks, tire marks, paint, a puddle's darkness, a sign on a wall (turn the entity so that its y points into the wall).
- `struct MeshInstances`
- `struct LodGroup` — LOD Group, as in Unity: a model drawn in full near the camera and simpler far from it. Under the entity it is on, the child called `far` (and what is under that) is drawn only beyond `distance` meters from the camera, and everything else only within it. What is not drawn still collides, moves and plays as it did: only what is drawn changes.

### Material

- `Vec4 baseColor{1, 1, 1, 1};` — linear RGB and opacity
- `float metallic = 0.0f;` — 0 plastic, wood, stone; 1 metal
- `float roughness = 0.6f;` — 0 mirror; 1 chalk
- `Vec3 emissive{0, 0, 0};` — light the surface gives off; above 1 it blooms
- `bool isDoubleSided = false;` — do not cull back faces
- `bool isUnlit = false;` — base color and emissive only, no lighting
- `bool isWater = false;` — A surface of water: the waves the scene's wind raises (Environment > Weather > Wind), the sky mirrored at a glancing angle, the bottom seen through it from above. Its base color is the color water this deep ends up; its opacity how murky it is (0.3 a clear sea that shows its bottom ten meters down, 1 a pond). On a flat mesh (a plane) the waves rise and fall, and things float on them (Water/Waves.hpp).
- `float waveSize = 1.0f;` — water: its waves' lengths, times what the wind makes them
- `float waveHeight = 1.0f;` — water: their height, times what the wind raises; 0 a mirror
- `float foam = 1.0f;` — water: how much white shows where waves break and at the shore; 0 none
- `bool isSea = false;` — the scene's sea, which the renderer makes itself (Environment > Water); never in a file
- `bool wasWater = false;` — Read from a file of before, when water was a material: the scene's sea takes the place of what it was on (Water/Water.hpp, retireOldWater). It is lit as any other now.
- `float sway = 0.0f;` — Moved by the scene's wind (Environment > Weather > Wind), the more the higher above the model's base: grass, reeds, leaves, a flag. 0 still; 1 grass; 0.1 a tree.
- `bool isSeenThrough() const;` — True for what the things behind it are seen through: drawn after everything opaque, from far to near, and casting no shadow. Water always is, whatever its blending says.
- `std::string shader;` — A shader written by hand: the name of a `.shader` file in Assets (see Rendering/SurfaceShader.hpp), or empty for the engine's own. It is given the surface as everything above made it, and returns what is lit.
- `struct ShaderValue` — What the material says for that shader's properties, by name. A property it does not mention has the value the shader file gives it.
- `std::string assetName;` — The material's file in Assets ("Materials/Brick.material") when it is an asset that scenes share; empty for one that belongs to a single scene or was made in code.
- `std::shared_ptr<Texture> baseColorTexture;` — sRGB
- `std::shared_ptr<Texture> normalTexture;` — tangent space, green up
- `std::shared_ptr<Texture> metallicRoughnessTexture;` — roughness in green, metalness in blue
- `std::shared_ptr<Texture> occlusionTexture;` — red
- `std::shared_ptr<Texture> emissiveTexture;` — sRGB

- `std::string meshName;` — The mesh's name where the mesh itself is not there: its file is missing, or the program has no GPU to hold it (a test, a tool that writes scenes). Written to a scene file as it was read, so that saving a scene does not forget what it could not load.

## Rendering/Particles.hpp

Particle emitters simulated on the CPU and drawn as camera-facing quads with one instanced draw call per emitter.

CPU particles are the right default for gameplay effects: a few hundred sparks, puffs of dust, a burst when something is collected. They can collide with game logic and cost almost nothing at these counts. (For hundreds of thousands of particles, move the simulation into a compute shader, as the Compute Shaders chapter of the site does.)

- `struct Particle`
- `struct ParticleEmitter` — Component: a particle system, made of the same modules as Unity's. Main and Emission say how many and for how long; Shape where they are born; Velocity, Forces and Noise how they move; Collision what they meet; Color and Size how they look over their life; Renderer how they are drawn. The emitter sits at its entity and emits along `direction` in the entity's own axes; with `space` World a particle is then left where it is, with Local it moves with the entity.
- `Vec4 particleColor(const ParticleEmitter& emitter, float t);` — The color and the size of a particle at a share of its life from 0 (born) to 1 (gone).
- `std::string writeEffect(const ParticleEmitter& emitter);` — An effect as text, one setting per line, and back: what a `.effect` file holds, so that an effect is made once and put on as many entities, in as many scenes, as use it.
- `bool setEffectValue(ParticleEmitter& emitter, const std::string& key, const std::vector<float>& values);` — One setting by name ("rate", "colorStart"...) from the numbers that follow it. False for a name nobody knows.
- `bool setEffectText(ParticleEmitter& emitter, const std::string& key, const std::string& value);` — The same for the settings that are words ("texture"). False for a name nobody knows.
- `std::vector<std::string> effectExtras(const ParticleEmitter& emitter);` — The settings that the two `particles` lines of a scene file do not hold, as "key numbers" lines; only what is not the usual.
- `inline Vec3 particleWorldPosition(const ParticleEmitter& emitter, const Particle& particle, const Mat4& world);` — Where a particle is in the world: its own position, carried by the entity's matrix if it lives in its space.

### Particle

- `float rotation = 0;` — radians, of its picture
- `float spin = 0;` — radians a second
- `float sizeScale = 1;` — its own size, from the emitter's size variation
- `float shade = 1;` — its own brightness, from the emitter's shade variation
- `float frame = 0;` — the frame of the sheet it starts on

### ParticleEmitter

- `float rate = 20.0f;` — particles per second while isEmitting
- `float spread = radians(25.0f);` — half-angle of the emission cone; pi emits in every direction
- `float spawnRadius = 0.0f;` — particles start inside a sphere of this radius
- `Vec4 colorStart{1, 1, 1, 1}, colorEnd{1, 1, 1, 0};` — linear RGB; values above 1 feed the bloom
- `float windInfluence = 0.0f;` — How much the scene's wind carries the particles: 0 for sparks that ignore it, 1 for smoke that goes wherever the air goes.
- `int burstAtStart = 0;` — Particles emitted at once when the emitter first runs: an explosion, a puff of dust.
- `enum Shape { Cone, Box, Ring, Sphere, Hemisphere, Line }` — Cone: inside a ball of `spawnRadius`, leaving along `direction` within `spread` (what a file without a shape means). Box, Ring and Line: inside a box, on a circle across the direction, along a line `boxSize.x` long; they also leave along the direction. Sphere and Hemisphere: on or in a ball, leaving outward from its middle.
- `bool fromShell = false;` — Sphere, Hemisphere, Box: born on the surface, not inside
- `Vec3 boxSize{1, 1, 1};` — Box: inside a box this large, in the entity's own axes
- `bool hasMiddle = false;` — fire: yellow, then orange, then smoke
- `float middleAt = 0.3f;` — at this share of the life
- `float burstEvery = 0;` — seconds between bursts; 0 for none
- `int burstCount = 10;` — particles in each
- `float duration = 0;` — it emits for this long and stops; 0 for as long as it is there
- `bool loops = false;` — with a duration: starts over when everything it made is gone
- `float stretch = 0;` — drawn as a streak this many seconds of its movement long: rain, sparks (0: a dot)
- `float turbulence = 0;` — meters per second of swirling, as in smoke that curls
- `float turbulenceSize = 1.0f;` — how large the swirls are, in meters
- `bool randomRotation = false;` — each starts turned at random (smoke, debris)
- `bool isRing = false;` — without a picture: a thin ring instead of a round dot (a ripple on water)
- `float spinMin = 0, spinMax = 0;` — radians a second each turns at, chosen between these
- `bool collides = false;` — bounces off the colliders of the scene (boxes, spheres, capsules)
- `bool bounces = false;` — off a level floor
- `float bounciness = 0.4f;` — how much of its speed a particle keeps when it lands
- `enum Space { World, Local }`
- `Space space = Space::World;` — World: left behind as the entity moves (smoke, a trail). Local: carried along (a halo)
- `float simulationSpeed = 1.0f;` — 2 plays it twice as fast
- `float startDelay = 0;` — seconds before it starts emitting
- `bool prewarm = false;` — starts as if it had been running already: a fire already burning
- `float sizeVariation = 0;` — 0 to 1: each particle a little smaller or larger
- `float shadeVariation = 0;` — 0 to 1: each a little darker or brighter
- `float inheritVelocity = 0;` — the share of the entity's own movement each is born with
- `float ratePerMeter = 0;` — emitted for every meter the entity moves: a trail
- `Vec3 drift{0, 0, 0};` — meters a second every particle moves along, in the system's space
- `float radial = 0;` — meters a second away from the emitter (below 0: toward it)
- `float orbital = 0;` — turns round the emitter's direction, radians a second
- `float buoyancy = 0;` — meters a second each second upward at birth, cooling to none: hot gas rises
- `float turbulenceSpeed = 1.0f;` — how fast the swirls themselves change
- `int turbulenceOctaves = 1;` — 1 to 3: swirls inside swirls, as real smoke has
- `float friction = 0.2f;` — how much of its speed along a surface a particle loses when it hits
- `float lifetimeLoss = 0;` — the share of its life a particle loses each time it hits
- `bool diesOnHit = false;` — gone when it hits: rain on a roof
- `float sheetFps = 0;` — frames a second; 0: the whole sheet once over its life
- `bool randomFrame = false;` — each starts on a frame of its own
- `enum RenderMode { Billboard, Stretched, Horizontal, Vertical }` — Billboard: a square facing the camera. Stretched: a streak `stretch` seconds of its way long. Horizontal: lying flat (ripples, a glow on the ground). Vertical: upright, turning to the camera round its up axis.
- `float softness = 0;` — meters: fades out where it meets a surface, instead of a hard line
- `float lit = 0;` — 0: its own color, glowing; 1: lit by the sun and the sky like smoke or dust

- `float burstTimer = 0, age = 0;` — since the last burst, and since it began
- `Vec3 lastOrigin{0, 0, 0};` — where the emitter was the update before: what it emits is spread along the way
- `float distanceAccumulator = 0;` — meters moved, for the rate per meter

## Rendering/Renderer.hpp

Draws a Scene.

Every frame goes through the same sequence of passes:

1. shadow maps     the scene seen from the sun, once per cascade        (depth only)
2. depth pre-pass  depth and normals of what the camera sees            (only if SSAO is on)
3. SSAO            how hidden each pixel is from the sky, then a blur
4. main pass       opaque objects, sky, transparent objects, particles, debug lines
```cpp
                 into a multisampled, floating-point (HDR) target
```

5. bloom           bright areas blurred through a chain of smaller and smaller textures
6. final pass      tone mapping onto the screen, then the 2D canvas on top

Before any of that, the renderer walks the scene once and builds plain lists of what to draw ("extraction"): it finds the camera and the lights, drops objects outside the view, sorts, and groups objects that share a mesh and a material into instanced draws.

- `struct SkySettings` — The colors are radiance, in the same units as light intensities. A clear sky is several times darker than a white wall in sunlight; keeping that ratio is what makes shadows read.
- `struct WeatherSettings` — The weather of a scene (Kit/Weather.hpp): none by default.
- `struct SeaSettings` — The scene's sea: water everywhere below a level, unless it is turned off (Environment > Water). Its waves are the wind's and the weather's (Environment > Weather): nothing here sets them. Under its level all is under water: seen through it from above, lit through it (dimmer and bluer the deeper, with the sun's light gathered into moving lines by the waves), and seen from inside it when the camera goes under. How it looks is set here, from a real sea to a lagoon in a cartoon. (Water of a game's own, a pond or a pool, is a surface shader: Assets > New > Water Shader.)
- `inline Vec3 sunlightThroughAir(float height);` — What reaches the ground of sunlight that crosses the air, for a sun `height` (the sine of its elevation): white high up, gold, orange and red toward the horizon, none once it has set. Relative to the sun overhead.

### SkySettings

- `Vec3 groundColor{0.11f, 0.14f, 0.19f};` — what is seen, and reflected, below the horizon
- `float sunDiskIntensity = 30.0f;` — how much brighter than the sunlight the disk itself looks
- `float cloudCoverage = 0.0f;` — 0 a clear sky, 1 overcast
- `bool cloudsHaveDepth = false;` — clouds as volumes one looks through, lit from the sun's side, instead of a flat layer
- `float cloudScale = 1.0f;` — larger numbers make smaller clouds
- `Vec2 cloudSpeed{0.012f, 0.004f};` — how fast the wind carries them
- `float cloudHeight = 1500.0f;` — meters: the base of the clouds with depth, which a camera can fly into
- `float cloudThickness = 1200.0f;` — meters from their base to their tops
- `int cloudSteps = 48;` — Clouds with depth are walked through along each line of sight: in so many steps (32 is coarse, 64 fine), into a picture this share of the scene's size (they are soft: half the size shows no loss and costs a quarter). The project's quality level sets both.
- `float stars = 1.0f;` — at night: 0 none, 1 a clear night far from any town
- `float moon = 1.0f;` — At night (with sunset colors), the moon: across the sky from the sun, it lights the scene with a cold, dim light and casts its shadows. 0 a night with no moon; 1 a full moon.
- `bool sunsetColors = true;` — The colors of sunrise and sunset by themselves: as the sun nears the horizon its light goes gold, orange and red through the thicker air, the sky around it glows, the clouds are lit from below, and when it has set the sky darkens into night.

### WeatherSettings

- `float rain = 0.0f;` — 0 none, 1 a downpour: drops around the camera, splashes, rings on water; the sky clouds over
- `float storm = 0.0f;` — 0 none, 1 lightning every few seconds: bolts in and under the clouds, lighting them from inside
- `float snow = 0.0f;` — 0 none, 1 a heavy fall: flakes drifting down round the camera
- `bool snowSettles = false;` — what falls lies: what faces up and is out in it turns white, more the longer it snows
- `float snowCover = 0.0f;` — how much has settled now, 0 to 1: the world's (World::weatherNow), never saved
- `float flash = 0.0f;` — the lightning's light this frame: the world's (World::weatherNow), not the scene's; never saved
- `Vec3 strikePlace{0, 0, 0};` — and where its stroke is: x and z, and the height of the ground it strikes (never saved)
- `float bolt = 0.0f;` — the shape of its bolt down to that ground; 0 a flash inside the clouds only (never saved)
- `float clouded() const;` — How much the weather hides the sun and fills the sky with cloud: 0 clear, 1 overcast.
- `float addedWind() const;` — How much harder than the scene's own the wind blows in this weather, in meters a second: a shower freshens it, a storm makes a gale of it.
- `float leastGusts() const;` — And how gusty it is at least.

### SeaSettings

- `bool enabled = false;` — a new scene of the editor has it; a scene of before, or one made in code, not
- `float level = 0.0f;` — meters: where its surface rests
- `Vec3 color{0.02f, 0.13f, 0.2f};` — its color where it is deep: what is left of white light after a long way through it
- `Vec3 shallowColor{0.16f, 0.62f, 0.58f};` — the color it takes over a light bottom, a meter or two down (turquoise over sand)
- `float clarity = 8.0f;` — meters: how far down, and how far across under it, one sees through it
- `float scattering = 1.0f;` — how much light its body sends back up: 0 dark water, 2 a glowing lagoon
- `float reflections = 1.0f;` — how much it mirrors: 0 none, 1 as real water does
- `float ripples = 1.0f;` — the small waves on it: 0 a glassy surface, 1 a real sea's, 2 choppy
- `float caustics = 1.0f;` — the sun's lines of light on its bottom: 0 none, 1 as real, 3 drawn strong
- `float foam = 1.0f;` — white where it meets the shore and what stands in it
- `float whitecaps = 1.0f;` — white on the crests of waves that break (from a fresh breeze up): 0 never
- `bool lensThroughSurface = true;` — The camera going through its surface: the water's edge across the picture as it goes, the shake of going in, drops on the glass that slide off after coming out. Off: it just cuts.
- `Vec3 absorption() const;` — What a meter of it takes of each color of light: its deep color is what is left after a long way through it (red goes first, then green); its clarity is how far one sees.
- `static float clarityOfMurk(float murk);` — The clarity a murkiness of before (0 clear to 1 murky) amounts to.

The components the engine itself understands. Rendering, physics and particle components live next to the systems that use them.

- `enum LightType { Directional, Point, Spot, Area }`
- `struct Light` — A light shines along the -Z axis of its entity's Transform (directional and spot), or in every direction from its position (point).
- `struct Behavior` — Game logic attached to one entity. `update` runs once per frame, `fixedUpdate` once per physics step. Either may be empty.

### Camera

- `float fovY = radians(60.0f);` — vertical field of view, in radians
- `float orthographicHeight = 10.0f;` — world units visible from bottom to top

### Light

- `Vec3 color{1, 1, 1};` — linear RGB
- `float range = 10.0f;` — point and spot: no light beyond this distance
- `float innerConeAngle = radians(20.0f);` — spot: full brightness inside this half-angle
- `float outerConeAngle = radians(30.0f);` — spot: darkness outside this half-angle
- `bool castsShadows = false;` — the first directional light (the sun), and point and spot lights (as many as the quality allows)

## Scene/Scene.hpp

A small entity-component system.

An Entity is only an id. Data lives in components, plain structs that are stored packed together by type (a "sparse set" per component type), so that a system which walks every Transform or every RigidBody reads memory in order.

```cpp
Entity crate = scene.create("Crate");
scene.add(crate, Transform{.position = {0, 2, 0}});
scene.add(crate, RigidBody{});

scene.each<Transform, RigidBody>([](Entity e, Transform& t, RigidBody& body) { ... });
```

- `struct Entity` — A handle to an entity. The generation makes stale handles detectable: when an entity is destroyed its index is reused, but with a higher generation.
- `struct Transform` — Where an entity is. Positions, rotations and scales are relative to `parent` when there is one. `world` is filled in by Scene::updateTransforms().
- `struct Tag` — What kind of thing an entity is to the game ("Player", "Enemy"), and the layer it is on. Many entities share a tag; code asks for them by it, whatever they are called.
- `struct Name`

### Transform

- `bool isActive = true;` — Off: the entity, and everything under it, is not drawn, does not collide, and its components do not run. It stays in the scene, ready to be switched on.
- `bool isActiveInHierarchy = true;` — This entity and all its parents are active. Filled in by Scene::updateTransforms().
- `uint32_t stamp = 0;` — internal: the update that last computed `world`

### Tag

- `int layer = 0;` — 0 to 31: what it collides with, see Collider

## Scene/SceneFile.hpp

Scenes as text files: what an editor saves and a game loads.

The format is one statement per line, made to be read by people and compared by git:

```cpp
molten-scene 1
material "Stone"
  baseColor 1 1 1 1
  roughness 0.8
  baseColorTexture "Textures/tiles_basecolor.png"
entity "Crate"
  transform 0 2 0  0 0 0 1  1 1 1        position, rotation (a quaternion), scale
  mesh "cube" 0                          mesh name, index of its material in this file
  collider box 0.5 0.5 0.5  0 0 0  0
  body dynamic 1 0.1 0.6 0.05 1
```

Meshes and textures are stored by name; the file never contains their data. Lines a reader does not know are skipped, so files from a newer version still load.

- `struct NamedMaterial` — A material with the name it has in the editor and in scene files.
- `struct EditorOnly {};` — Marks an entity that belongs to a tool and not to the scene (an editor's own camera): it is never written to a file.
- `struct PrefabOverride` — A copy of a prefab placed in a scene, by reference: the scene keeps only this entity (its name, its place, the prefab's file); what the prefab holds is put under it each time the scene is read, so that a change to the prefab shows in every scene that has it. Prefabs may hold such copies of other prefabs. A value of a prefab's copy that is not the prefab's: changed on this copy only, kept in the scene as `override "Crate/Lid" MeshRenderer material "Materials/Red.material"`. The path is of names below the copy (its prefab's root first); the value as a variant's `set` takes it.
- `struct PrefabInstance`
- `bool applyPrefabValue(Scene& scene, Entity root, const PrefabOverride& change, const struct SceneAssets& assets);` — Changes one value of an entity found by its path below `root`, as variants and prefab overrides do. False if there is no such entity, component or field.
- `Entity entityAtPath(Scene& scene, Entity root, const std::string& path);` — The entity found by a path of names below `root` ("Body/Hat"; "" is root itself); invalid if none.
- `bool pathBelow(const Scene& scene, Entity root, Entity entity, std::string& path);` — The path of names from `root` down to `entity` ("" for root itself); empty and false if it is not below it.
- `struct FromPrefab {};` — Marks what a PrefabInstance put under itself: it comes from the prefab, and is not written.
- `bool isPrefabVariant(const std::string& text);` — A prefab variant: a prefab made from another (its base) with some values changed, as text:  molten-variant 1 base "Prefabs/Enemy.prefab" name "Fast Enemy"                                    the root's name set "" NavAgent speed "6"                            on the root set "Body" MeshRenderer material "Materials/Red.material" set "Body/Hat" Transform scale "1.5 1.5 1.5"  An entity is named by the path of names below the root. Transform takes position, rotation (degrees about x, y and z) and scale; MeshRenderer takes material; any component a game or the kit declares takes its fields by name.
- `struct SceneAssets` — How the names in a file become assets. Usually both lead to Assets (see sceneAssets()); either may be empty, and then meshes or textures are simply left out.
- `std::string writeMaterial(const Material& material);` — A material as the text of a `.material` file, and back. `texture` loads the textures the file names; without it they are left out.
- `std::string writeScene(Scene& scene, const std::vector<NamedMaterial>& materials, const RenderSettings& settings, const std::vector<Entity>* only = nullptr);` — The whole scene as text. Materials that are used by an entity but missing from `materials` are written too, under a made-up name.  With `only`, just those entities are written (a parent outside the list is forgotten), with the materials they use and without the scene's settings: this is how a prefab is made of part of a scene.
- `bool readScene(const std::string& text, Scene& scene, std::vector<NamedMaterial>& materials, RenderSettings& settings, const SceneAssets& assets, std::vector<Entity>* created = nullptr);` — Adds what the text describes to `scene` (clear it first to replace it) and replaces `materials`. Returns false, and logs why, if the text is not a scene file at all. `created`, if given, receives the entities that were added, in file order.

### PrefabInstance

- `std::string prefab;` — "Prefabs/Wheel.prefab"
- `bool setOverride(const PrefabOverride& change);` — Sets (or replaces) one; false if nothing changed.

### SceneAssets

- `std::function<std::shared_ptr<Material>(const std::string&)> material;` — A material that is an asset of its own, by its file's name in Assets.
- `std::function<std::optional<std::string>(const std::string&)> prefabText;` — A prefab's text, by its file's name in Assets: for prefabs inside prefabs, and variants.

## Script/Convert.hpp

A visual script written out as C++: the same events, the same steps in the same order, as a component a programmer can go on from. Each box of the graph becomes one call of the node of that name, so the code does exactly what the graph did.

```cpp
[On Update] ──▶ [Rotate degrees 180]        void update(World& world, Entity self, float dt) {
                                                script::Call call(world, self, dt, state);
                                                call("Rotate", {{"degrees", script::Value::number(180)}});
                                            }
```

The other way, from any C++ to a graph, cannot be done: code can say things boxes and wires have no shape for. Code that was made from a graph keeps the graph in a comment at its end, so that it can go back: the graph it was made from.

- `struct Call` — Runs single nodes from code: what the C++ made from a graph is written with.
- `std::string graphToCpp(const Graph& graph, const std::string& name, const std::string& source);` — The C++ of a graph, as a component called `name`. `source` is where the graph came from, for the comment at the top.
- `std::string graphToCppKeepingGraph(const Graph& graph, const std::string& name, const std::string& source);` — The same, with the graph kept in a comment at the end of the file: what can go back to boxes.
- `std::optional<Graph> graphKeptIn(const std::string& code, bool* wasChanged = nullptr, std::string* name = nullptr);` — The graph kept in C++ made from one, if there is one. `wasChanged` is set to true if the code was edited after it was made: the graph is then the one it was made from, not what the code does now.
- `std::string boxAsCppStatement(const Graph& graph, const Node& node);` — One box as a line of C++ that does what it does, for a box wired in among C++ boxes (Script/CppBoxes.hpp): it expects `world` and `self` where it is written, as a component's functions have them.
- `std::string typeNameFor(const std::string& fileStem);` — A name that can be a C++ type: letters and digits, starting with a capital letter.

### Call

- `std::string operator()(const char* type, Inputs inputs = {});` — Does what an action node does. Returns the name of the flow output it leaves by ("then"; "true" or "false" for a branch), or an empty text if it stops there.
- `Value value(const char* type, Inputs inputs = {}, const char* output = nullptr);` — The value of a node's output; the first, if none is named.
- `Value otherName() const;` — The name of the other entity of a collision or a trigger.

## Script/Graph.hpp

A visual script: boxes ("nodes") joined by wires. This file is the script as data; Script/Runtime runs it and the editor's graph panel draws it.

There are two kinds of wire. White ones carry the flow: "when this is done, do that". Colored ones carry a value: a number, a yes or no, a point in space, a text.

```cpp
[On Update] ──▶ [Rotate]            every frame, turn the entity
                 degrees ◀── [Number 90]
```

A script is a text file (.graph) in the project's Assets:

```cpp
molten-graph 1
node 1 "OnUpdate" 80 80
node 2 "Rotate" 320 80
  value "degrees" "90"
link 1 "then" 2 "in"
```

- `enum PinType { Flow, Float, Bool, Vec3, String }`
- `struct Value` — What travels along a colored wire. A value of one type can be read as another: a number as yes/no (not zero), a number as a point (the same in x, y and z), and so on.
- `struct PinDef`
- `struct NodeDef` — A kind of node: what it is called, its pins, and what it does.
- `class NodeLibrary` — Every kind of node there is. Script/Runtime adds the standard ones; a game or a plugin may add its own.
- `struct Node`
- `struct Link`
- `struct Graph`

### Value

- `void asVector(float& outX, float& outY, float& outZ) const;` — The three numbers of a point; a single number is repeated.
- `std::string toText() const;` — As written in a .graph file, and back. `type` says how to read the text.

### PinDef

- `std::string name;` — as in files and code: "degrees"
- `Value defaultValue;` — of an input nothing is wired to
- `std::string pick;` — a text input: what it holds, for the board to offer (see Field::pick); empty: free words

### NodeDef

- `std::string type;` — as in files: "Rotate"
- `std::string category;` — where the "add node" menu puts it: "Transform"
- `std::string title;` — on the node: "Rotate"
- `bool isEvent = false;` — starts a flow by itself: On Start, On Update
- `std::function<const char*(ExecContext&)> execute;` — For a node with a flow input: does its work and returns the name of the flow output to go on from ("then"; "true" or "false" for a branch), or nullptr to stop.
- `std::function<Value(ExecContext&, int output)> evaluate;` — For a node with value outputs: the value of output number `output`.

### Node

- `float x = 0, y = 0;` — where it is drawn
- `std::map<std::string, std::string> values;` — Values typed into inputs nothing is wired to, as text, by pin name.

### Link

- `std::string fromPin;` — an output
- `std::string toPin;` — an input

### Graph

- `const NodeLibrary* library = nullptr;` — The kinds of node it is made of: null for a visual script's (NodeLibrary::instance()); a shader graph has its own (Rendering/ShaderGraph.hpp). Not saved: whoever reads the file knows.
- `void removeNode(int id);` — Removes a node and every wire on it.
- `bool connect(int fromNode, const std::string& fromPin, int toNode, const std::string& toPin);` — Wires an output to an input. Refused (false) if the pins do not exist, if one is flow and the other is not, or if it would wire a node to itself. An input holds one value wire and a flow output leads to one place: an older wire there is replaced.
- `const Link* linkTo(int node, const std::string& inputPin) const;` — The wire that ends at an input, or the one that starts at a flow output.
- `static Graph starter();` — What a new script starts with: On Start and On Update, ready to be wired.

## Script/Runtime.hpp

Runs visual scripts (Script/Graph).

A script is run once per frame for every entity that has a VisualScript component. Each run looks at the script's event nodes (On Start, On Update, On Key Pressed...) and, for those that happened, follows the white wires from node to node. A node that needs a value asks the node its input is wired to, which may ask others in turn.

- `struct ScriptState` — What one entity's copy of a script remembers between frames.
- `struct ExecContext` — What a node sees while it runs.
- `struct Debugger` — Watching scripts as they run, for the editor's Visual Script panel: the last value that went along each colored wire, when each node last ran, and breakpoints. At a breakpoint the flow stops before the node, the game is held (wantsHold), and the node runs when it goes on.
- `void registerStandardNodes();` — Adds the nodes that come with the engine to the NodeLibrary. Safe to call again.
- `void runFrame(const Graph& graph, ExecContext context);` — One frame of one script on one entity: fires the events that happened. `context` supplies the scene, the input, the entity, dt and the state.
- `const Graph* loadGraph(const std::string& name, const std::string& filePath);` — The script with this name (a path relative to Assets), read from `filePath` the first time and again whenever the file changes. nullptr if it cannot be read.
- `struct VisualScript` — Component: runs a visual script on its entity while the game plays.

### ScriptState

- `std::vector<Entity> collidedWith, triggeredBy;` — since the script last ran
- `std::vector<Message> heard;` — messages since the script last ran
- `struct Waiting` — Flows stopped at a Wait (until a time) or a Wait Until (until its condition holds).

### ScriptState::Waiting

- `bool resumesHere = false;` — stopped at a breakpoint: the node itself runs when the game goes on

### ExecContext

- `const Node* node = nullptr;` — the node that is running
- `World* world = nullptr;` — may be null in a test of one node: then no shared values, sounds or scenes
- `Input* input = nullptr;` — may be null: then no key is down
- `Entity other;` — for collision and trigger events: who it was
- `const Message* message = nullptr;` — for On Message: what was heard
- `Entity self;` — the entity the script is on
- `float dt = 0;` — seconds since the last frame
- `double time = 0;` — seconds since the game started
- `int depth = 0;` — of values asking values: stops a loop of wires
- `std::string graphName;` — the script's file, for the Debugger
- `Value input_(const char* pin);` — The value of one of the running node's inputs: from the wire, or what was typed in.

### Debugger

- `bool isOn = false;` — while the editor shows a script and the game runs
- `std::string graph;` — the script watched
- `Entity entity;` — which entity running it; none: the first to run it
- `std::map<std::pair<int, std::string>, std::string> values;` — (node, output) -> its last value, as text
- `std::map<int, double> ran;` — node -> when it last ran, in game time
- `std::set<std::pair<std::string, int>> breakpoints;` — (script, node)
- `bool stepsOnce = false;` — stop at the next node that runs, wherever it is
- `bool wantsHold = false;` — set at a stop: the editor holds the game
- `double now = 0;` — the game time of the frame being run
- `void clearSeen();` — Forgets what was seen: another script, or another play.

### Debugger::Stop

- `int node = 0;` — 0: not stopped

### VisualScript

- `std::string graph;` — the script: a .graph file, as a path relative to Assets
- `script::ScriptState state;` — not saved: every play starts fresh

## UI/Gui.hpp

A small immediate-mode user interface for tools: panels, buttons, number fields, text fields, lists, pop-up menus and icons, drawn with the Canvas.

"Immediate mode" means the interface is not built once and kept: every frame the program says what is on screen, and each call both draws a control and reports what the user did with it:

```cpp
gui.beginPanel("Light", Vec2{16, 16}, Vec2{280, 200});
gui.dragFloat("Intensity", light.intensity, 0.05f, 0.0f, 100.0f);
if (gui.button("Reset")) light = Light{};
gui.endPanel();
```

There is no list of widgets to keep in step with the data: the data is the only state. The few things the Gui itself must remember between frames (which control is being dragged, which text field has the keyboard, how far a panel is scrolled, which sections are folded) are keyed by an id computed from the panel's title and the control's label.

How it looks follows three rules. Things to fill in (fields) are darker than the panel they sit on, like wells; things to press (buttons) are lighter, like keys. The accent color is spent only on what is selected or being changed. And nothing is an image: icons are a few lines and curves drawn by the Canvas, sharp at any size.

The engine's editor is built with this, and a game can use it for menus and debug panels. It only needs a Canvas and an Input, so it is tested without a GPU.

- `class Gui`

### Gui

- `enum Icon { None, Move, Rotate, Scale, Play, Stop, Undo, Redo, Save, Add, Trash, Copy, Cube, Light, Camera, Empty, File, Image, Material, Check, ChevronRight, ChevronDown }` — The pictures a button or a list row can carry.
- `void begin(Canvas& canvas, const Input& input);` — Call once per frame before any control, and end() after the last one.
- `bool wantsMouse() const;` — True if the pointer is over a panel or a control is in use: the program should then leave the mouse alone (not select or move things in the 3D view).
- `bool wantsKeyboard() const;` — True while a text field has the keyboard: the program should ignore its shortcuts.
- `bool changed() const;` — True if any control changed a value during this frame.
- `bool isBusy() const;` — True while a control is being dragged or edited: an edit that is not finished yet.
- `bool section(const std::string& title, bool startsOpen = true);` — A title that folds what follows it. Returns true while open: put the controls of the section inside `if (gui.section("Transform")) { ... }`.
- `int buttonRow(const std::vector<std::string>& labels);` — Several buttons on one row. Returns the position of the one clicked, or -1.
- `bool tabs(const std::vector<std::string>& labels, int& current);` — Like buttonRow, but one stays selected.
- `bool selectable(const std::string& text, bool selected, float indent = 0.0f, Icon icon = Icon::None);` — A row of a list: highlighted when `selected`, returns true when clicked.
- `bool dragFloat(const std::string& label, float& value, float speed = 0.01f, float minimum = -std::numeric_limits<float>::infinity(), float maximum = std::numeric_limits<float>::infinity());` — A number changed by dragging sideways; a click without dragging lets you type it. With both a minimum and a maximum, the field also shows where the value is between them.
- `bool color(const std::string& label, Vec3& value);` — Three numbers and a swatch. Colors are linear; values above 1 are allowed (they bloom).
- `bool textField(const std::string& label, std::string& value);` — Returns true when the text was changed and confirmed (Enter, or a click elsewhere).
- `bool combo(const std::string& label, int& index, const std::vector<std::string>& items);` — A pop-up list. `index` may be -1 for "nothing chosen".
- `void bar(Vec2 position, Vec2 size);` — A strip of window chrome. The pointer over it belongs to the interface.
- `void card(Vec2 position, Vec2 size);` — A rounded surface that floats over the 3D view, with a shadow.
- `bool iconButton(Icon icon, Vec2 position, Vec2 size, const std::string& tooltip, bool isSelected = false);` — `tooltip` appears when the pointer rests on the button.
- `void icon(Icon icon, Vec2 center, float size, Vec4 color);` — Draws an icon, centered, `size` points wide.

### Gui::Style

- `float spacing = 4.0f;` — between rows
- `float padding = 10.0f;` — inside a panel
- `float labelWidth = 0.36f;` — share of a row taken by the label of a field
- `float radius = 4.0f;` — of the corners of fields and buttons
- `Vec4 chrome = rgb(0x1b1d22);` — bars along the edges of the window
- `Vec4 well = rgb(0x17191d);` — fields: darker than the panel
- `Vec4 raised = rgb(0x343840);` — buttons: lighter than the panel
- `Vec4 raisedHot = rgb(0x424752);` — a button under the pointer
- `Vec4 line = rgb(0x101216);` — between panels, and around pop-ups
- `Vec4 accent = rgb(0xfe8b3c);` — the accent: selection and changes only

## UI/Splash.hpp

The screen shown for a moment when a game made with the engine starts: the engine's logo, and the game's name underneath. (The editor has none: it opens on its projects.)

- `struct Splash`

### Splash

- `static constexpr float kDuration = 2.4f;` — seconds on screen, the fade at the end included
- `static constexpr float kFade = 0.5f;` — the fade at the end: the game shows through it
- `static void draw(Canvas& canvas, float seconds, std::string_view subtitle, const Texture* logo = nullptr);` — Draws the splash over the whole canvas. `seconds` is the time since it appeared. It fades in, stays, and fades out to show what is behind it. With `logo` (the engine's Assets/Branding/logo.png, 2400 x 536) that picture is shown; without it, the name in letters.
- `static bool isOver(float seconds);` — True once the splash has faded away and nothing more needs to be drawn.
